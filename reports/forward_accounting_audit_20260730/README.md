## Q2 — 日报「前向净利」的计算路径复现 + 跳变根源

**计算路径（代码审读，`mode_push`→`gate_status`→`forward_window`）**：

```
forward_net = f_per.sum()
其中 f_per = perbar[ perbar.index >= effective_forward_start ]  再剔除 gap 区间
effective_forward_start = max(config.forward_start_utc, deploy.first_live_bar_close_utc)
                        = max(2026-06-21T08:00Z, 2026-06-21T08:00Z) = 2026-06-21T08:00Z（固定）
```

**用户核心假设「前向净利 = 全历史账 − 部署时刻基线，且基线跳动」→ 用代码+数据证伪**：

1. **代码里根本没有减法**。`forward_net` 是对前向切片 `f_per` 的**直接求和**，
   不是「全历史总额 − 某基线」。`deploy.json` 中**不存在任何净值基线字段**
   （只有两个时间戳 + note）——「部署时刻基线」这个被减数在本代码中**不存在**，
   减法假设结构上不可能成立。
2. **锚点不跳动**。`effective_forward_start` 取 config 与 deploy 的 `max()`，两者
   都恒为 2026-06-21T08:00Z，config_sha256 全程不变（reconcile 里 `001b0d9e…`）。
   这正是 2026-06-22 修补的产物（`forward_start_note` 注释在案）。

**跳变真正根源 = always-in 5 币组合的盯市端点本身在波动**。独立重推的逐日前向
M2M 区间从 **−$878.90 到 +$1,116.71**（见 `reconstructed_forward_ledger.jsonl`）；
日报是**每日 push 在各自盘中 run-time 的偏切片快照**（末桶按 `ceil("D")` 未完整）。
所以显示的前向净利合法地忽上忽下，**既非基线跳动、也非回填污染**。
独立重推复现了净利的**量级带（$1,200–2,400）与晚 7 月下行趋势**，且回撤结构 cent 级吻合
（Q3）——这是「账本健康」的样子，不是「账本被污染」的样子。

## Q3 — 回撤恒定 $2,074.29 的根源

**根源 = 指标名不副实（是最大回撤，标签写成「当前回撤」），而非锚点写死 / 序列停更。**

代码 `gate_status`：`maxdd = float((eq.cummax() - eq).max())` —— 这是**整个前向窗口的
最大回撤（MAX drawdown）**，日报却标为「**前向当前回撤**」。

独立重推前向净值路径（`[3]` + `reconstructed_forward_ledger.jsonl`）：

- 前向净值**高水位 = $2,430.61 @ 2026-07-02**；
- 回撤谷底 **$356.32 @ 2026-07-09** → **max-DD = 2430.61 − 356.32 = $2,074.29**
  （与报告值 **cent 级精确吻合**）；
- max-DD 记录在 **2026-07-09 定格**，此后端点在 $1,077–$2,235 之间游走，
  **从未再跌破谷底 $356.32**（触发新纪录需净值 < 2430.61 − 2074.29 = $356.32），
  故 max-DD **正确地恒为 $2,074.29**。

**判定**：**不是**峰值锚点被写死、**不是**序列停更——是 max-DD 语义下「一个早期
（07-02→07-09）回撤纪录至今未被打破」的**正常表现**。唯一缺陷是**标签**：
「当前回撤」应为「最大回撤(max-DD)」。真正的「当前净值距峰回撤」现值应是
$2,430.61 − $1,236.79 = **$1,193.82**，与显示的 $2,074.29 不是一回事。

> 这条 cent 级吻合（$2,074.29）是本审计**最强的一块证据**：max-DD 是整条前向净值
> 路径的结构特征（峰@07-02、谷@07-09），若历史被回填/篡改，它极难还恰好等于
> $2,074.29 到分。独立重推从完整账本无 gap 排除即精确复现，等价于 funding 审计里
> 那个 $5×10⁻⁵ 的「舍入地板级」确认——**前向记账核心是干净的**。

## Q4 — 独立重推 vs 日报：三天真实值对比 + 矛盾定位

主口径（06-22，最贴近引擎 per-bar ≥08:00Z 切片；恒定回撤 $2,074.29 贯穿）：

|---|---:|---:|---:|---:|---:|

| 2026-07-24 | −590.99 | **1,579.62** | 2,074.29 | 2,227.46 | −647.84 |
| 2026-07-29 | +122.35 | **1,370.95** | 2,074.29 | 1,251.67 | +119.28 |
| 2026-07-30 | −126.08 | 1,244.88 | 2,074.29 | — | — |
| 2026-07-31 | −8.09 | 1,236.79 | 2,074.29 | — | — |

**偏离定位**：累计净利偏离方向/量级不定（−124 / −648 / +119），**不是一个固定
偏移**（若是简单「起点常量减法」应为常数偏移）。根源 = **盘中偏切片 + 波动端点的
计时差**：日报在各自 run-time 用**未完整的 `ceil` 末桶**求和，本快照是 7/30 的
**完整桶**。回撤（结构量）cent 精确吻合、净利（最易变端点）量级/趋势吻合，
恰恰指向**计时差而非历史篡改**。

**矛盾 2 复现与拆解**（`[5]`）：日报「当日模拟 M2M **+$2.86**」= 最后一个
`ceil("D")` 桶——因 ceil 约定，该桶主要由**前一日历日**的 4h bar 组成；而「累计
−$66.83」是**两次 run 之间新增 bar** 的端点差——**两者是不同的 bar 集合，本就不该
相等**，故「当日赚钱、累计却跌」**不是数学矛盾，是两个同名不同义的量**。
（佐证：本快照完整的 7/24 桶实为 **−$590.99**，说明日报当时的 +$2.86 是尚未灌入
亏损 bar 的偏切片瞬照。）

**矛盾 1**：净利下行而回撤恒定——见 Q3，「当前回撤」实为 max-DD，早期纪录未破故恒定，
是标签误导 + 用户对「当前 vs 最大」的合理误解，非矛盾。

**矛盾 3**：K2 余量 $30,408 = $32,482.54 − $2,074.29 恒定——是矛盾 1 的下游，
**算术正确、gate 正确**（K2 阈值 = baseline p95 max-DD $25,986.03 × 1.25 = $32,482.54，
与用户 $32,483 吻合）。

## Q5 —【核心】gate 判定用哪套账？bug 在显示层还是 gate 层？

**回答：bug 只在「显示 / 标签层」；gate 判定的输入数字是对的；前向观察有效性未受损。
→ 用户无需碰 VPS。**

论据链：

1. **gate 与显示同源**。K1/K2 在 `gate_status()` 内、由**同一个前向切片 `f_per`**
   算出（`K2_triggered = maxdd > k2_p95*1.25`；`K1_triggered = roll12 < k1_p5`）。
   日报的「前向净利 / 回撤」也取自同一个 `gs`。**不存在**「gate 读自洽核心账、显示读
   另一套错账」的分裂——它们是**同一次计算**。heartbeat 的 $73,614/484 全历史数
   **不是 gate 输入**（只是监控）。

2. **但这套同源计算是对的**（不是「同错」）：
   - **K2 的输入 max-DD = $2,074.29 经独立重推 cent 级证实正确**；阈值 $32,482.54，
     余量 $30,408。盘中偏切片噪声（数百美元级）**无法**把 $2,074 的 max-DD 推到
     $32,483，K2 **稳健地远未触发**。
   - **K1 需 ≥12 月才激活**，前向仅 ~1.3 月 → **K1 未激活**（日报显示 `K1_note`），
     **不可能误触发/漏触发**。

3. 三个「矛盾」全是**显示/标签层伪影**（max-DD 误标为当前回撤；`ceil` 末桶「当日
   M2M」滞后约一日；always-in 端点真实波动被误读为不一致），**不是 gate 输入的
   计算错误**。

**结论**：**bug 层级 = 仅显示层，gate 正确**。前向观察（phase-1 判 KILL/UPGRADE 的
能力）**有效性完好**。用户**可暂不修、不碰 VPS，让日报先「标签难看」地跑着**。

## Q6 — 修复方向建议（仅建议，不执行）

**首要建议：现在不碰 VPS。** 理由：(a) gate 输入正确、无误触发风险；(b) phase-1 的
全部价值在于一段**未经触碰、连续**的前向样本，任何代码改动都与「零优化/零触碰」
的冻结伦理相悖，且需再走一遍三角色部署，为「让标签好看」付出连续性风险不划算；
(c) 让日报保持现状**不损失任何有效性**——要看的数（gate）是对的。

**若日后确实想让日报更清晰**（低优先级、可与其他维护批处理，且**纯显示层**、
**不碰 `f_per`/gate 数学/config_frozen**）：

1. 「**前向当前回撤**」→ 正名为「**前向最大回撤 (max-DD)**」（值本就是 max-DD）；
   如需「当前距峰回撤」可另加一行（现值 $1,193.82）。
2. 「**当日模拟 M2M**」标注清楚它是 `ceil("D")` 末桶（主要含**前一 UTC 日** bar），
   或改为「自上次 run 以来增量」——**仅改显示，不改 gate**。
3. 三处都在 `mode_push` 的显示串（+ 「current」→「max」措辞）；**均不触及引擎、
   `f_per` 计算、config_frozen、gate 逻辑**，故不会改动 config_sha256（selfcheck 哈希
   的是 config_frozen.json，非 .py）。

**是否影响前向连续性**：纯显示层改动**不改** `f_per`/gate 数学，前向 P&L 连续性
保持；但按冻结伦理仍应最小化触碰。**是否碰 VPS、是否值得部署，全交用户决策。**

## Q7 — 是否登记 prior-registry Level 3？（交用户确认，本任务不登记）

用户初始假设「forward_provenance 回填污染（Level 3，起点锚定错误）」——**本审计证伪
了这个具体归因**：起点锚定正确、warmup 被正确排除（S2）、回撤 cent 级吻合，**不是**
provenance/锚定类的实现失败。

但存在一个**较轻的 Level-3（实现失败·可预防）候选**，值得登记为可复用先验：

> **「全量重算式前向包装器的『显示层自相矛盾』陷阱」**：当一个 full-recompute 前向
> 系统同时呈现 (a) 名为「当前回撤」实为 max-DD 的指标、(b) 按 `ceil("D")` 桶化、
> 滞后约一日的「当日 M2M」、(c) always-in 组合真实波动的端点净利，**即便 gate 数学
> 完全正确，对人也会显得自相矛盾**。诊断纪律：**先用独立重推区分「显示层混淆」与
> 「gate 层污染」，再决定是否触碰系统**——本例正是「怀疑被数据干净否证」= 与发现
> 真问题同等价值的确认性审计。**关联** `[[forward_b2_4h_system]]`。

**是否登记、如何分级，交用户确认。** 本任务不写入 registry。
